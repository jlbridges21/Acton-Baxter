# Integration capabilities

Status as of 22 Oct 2026. The **Integrations** tab shows the live status and runs read-only connection tests.

Credentials live only in server environment variables and are never shown in the app. When a system isn't available, an approved action becomes a **manual task** that carries the exact text or change, and a person records that it was done.

## Behavior on failure

| Response                      | What happens                                                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `401` / `403`                 | Not retried. The action shows "rejected the credentials or permission", and an administrator fixes access and presses **Retry** |
| `429` / `5xx` / network error | Retried automatically by the sweep, up to 5 attempts, with no duplicate execution                                               |
| Other `4xx`                   | Not retried; the response text is shown                                                                                         |
| Not connected                 | `manual_required` with exact instructions                                                                                       |

## Research notes

These are the sources checked when this was built:

- **BambooHR:** the API documentation describes the employee update and field-metadata endpoints. No survey or eNPS endpoints were found.
- **Betterteam:** no developer API documentation was found.
- **DocuSign:** eSignature REST API v2.1 with the JWT grant. The demo authorization host is `account-d.docusign.com`, and production needs go-live approval.
- **JobTread:** the `timeEntries` count was verified as 0 through the existing Pave connection.
